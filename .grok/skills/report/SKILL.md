# Фабрика отчёта

Сессия и все команды — из корня репо (`AGENTS.md`, `tools/`). Не запускать пайплайн, пока cwd не корень. Эталон `sample.docx` не писать. Word не собирать с нуля и не через Composio.

Пользователь **не сортирует файлы и не прикладывает PDF в чат**. Всё лежит прямо в `subjects/<предмет>/`: задание, лекции, слайды — одним ворохом.

Не создавать inbox/lectures/materials. Не просить разложить PDF по папкам.

## 0. Превью

Нет `student.yaml` — скопировать из `student.yaml.example`, остановиться пока не заполнят ФИО.

```
python tools/pickup.py --preview --json
```

- код 0 — JSON `[{subject, pdf, md}, ...]` на каждый PDF **в корне предмета** (не внутри `lab-*`)
- код 2 — PDF нет: «положите файлы в subjects/<предмет>/»
- код 1 — ошибка

Прочитать каждый `md` целиком и картинки. По содержанию, не по имени:

- задание: лабораторная/практика, «выполнить», варианты, цель/ход работы
- контекст: лекция, конспект, слайды, методичка — пригодится при выполнении, но это не сама работа

Несколько файлов одного задания (часть 1 и 2) — одна лаба, все в `--assignment`. Две разные лабораторные — два `--claim`. Контекст не делать отдельной lab-папкой.

Нет `title-fields.yaml` / `confirmed` — онбординг эталона, работу не начинать.

```
python tools/pickup.py --claim --subject S --assignment "<задание.pdf>" [--assignment "<часть-2.pdf>"] [--context "<лекция.pdf>"] [--context "<ещё.pdf>"]
```

Все эти PDF окажутся **плоско** в папке работы (без подпапок типа lectures/). Корень предмета снова пустой от PDF — следующую работу снова кидают туда же.

## 2. Выполнить всё задание

Пока в `checklist.md` есть `- [ ]` — отчёт не готов.

Нет инструмента:

1. MCP `search_tool`
2. Composio connect
3. GitHub/CLI (`web_search`)
4. Не писать «не могу, нет Postman»

Скриншоты. Страницы открывать в изолированном контексте (`new_page` + `isolatedContext: "report"` — как инкогнито). После загрузки **до снимка** закрыть всплывашки: `evaluate_script` со скриптом из `tools/dismiss_popups.py` (`dismiss_script()`). База: cookie («Принять все», Allow all, Allow essential). Пока попап перекрывает контент — скрин не годится. Затем `screenshot.py --from-file`, осмотр, `--mark-ok`.

Текст `report.md`: обезличенный, цельные абзацы (не одно предложение на абзац). Без ярлыков вроде «Наблюдение.» и без цитирования вопросов задания — ответ встраивается в связный текст так, чтобы было ясно, на что он отвечает. Оглавление в md не писать. Сборщик вставляет заголовок «СОДЕРЖАНИЕ» стилем Heading 1 эталона и настоящий блок Word (элемент «Оглавление» / Table of Contents + поле TOC по Heading 1–2). В Word: клик по оглавлению → «Обновить поле». Не набирать содержание точками вручную.

Списки, таблицы, листинги в `report.md` — штатные блоки сборщика, не имитировать в Word вручную:

- ненумерованный список задания: строки `– пункт` (клон абзаца «– » эталона). Не `1.` и не Word-буллеты.
- таблица: `Таблица: подпись` + GFM-таблица. Число ячеек в каждой строке = числу столбцов шапки; `|` внутри ячейки писать как `\|`. «Продолжение Таблицы N» ставит `continue_tables.py` после вёрстки, только у куска, который Word реально перенёс на следующую страницу — не резать таблицу заранее.
- между рисунком и рисунком, рисунком и таблицей, таблицей и таблицей всегда абзац текста, не объекты вплотную.
- листинг: `Листинг: подпись` и fenced code. Сборщик ставит курсивную подпись слева и код Courier New 10 пт в рамке. Готовая строка «Листинг 1.1 — …» перед кодом тоже годится.
- рисунок: `![подпись](screenshots/…)` — абзац текста рядом обязателен. Высоту подгоняет `fit_figures.py` после вёрстки: если рисунок уехал на следующую страницу и на предыдущей осталась дыра, он сжимается и встаёт в этот остаток. Не оставлять пустой низ страницы перед рисунком.

С новой страницы сборщик ставит: каждый нумерованный H1 (1 …, 2 …), «ЗАКЛЮЧЕНИЕ», «СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ», «ПРИЛОЖЕНИЯ». «Приложение А/Б/…» сразу после «ПРИЛОЖЕНИЯ», без разрыва страницы. ЦЕЛЬ/ЗАДАНИЕ — без разрыва.

Таблицы по ширине полей, шапка белая.

Mermaid вместо image generation, если хватает.

`work.yaml` + `report.md` по эталону. Второй автор той же практики: `python tools/new_work.py --subject S --slug SLUG-фамилия --number N --student path/to/student.yaml` — номер практики тот же, папка другая. Корневой `student.yaml` не трогать.
