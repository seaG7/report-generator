# report-generator

Фабрика учебных отчётов: PDF из папки предмета → выполнение задания → `.docx` правкой копии эталона.

## Откуда запускать

Только из **корня репозитория**: `D:\Reps\report-generator` (там `AGENTS.md`, `tools/`, `subjects/`).

Не из `subjects/`, не из `lab-*`, не из `tools/`. Скрипты и скиллы ждут cwd = корень. Если сессия открыта глубже — сначала перейти в корень, команды вида `python tools/...` без смены диска/папки не гонять из вложенной директории.

Пользователю достаточно: открыть этот репозиторий в Grok и написать `/report` или «сделай отчёт».

## Что делает пользователь

Один раз: `student.yaml` (из `student.yaml.example`), на предмет — `subjects/<slug>/sample.docx` (чужая правильно оформленная работа).

Каждая работа: **все PDF скопом** в `subjects/<slug>/` (задание + лекции + что угодно). Сортировать, переименовывать, класть в inbox — не просить. В чат PDF не прикладывают.

Готовый файл: `subjects/<slug>/lab-NN-<имя>/report.docx`.

## Дерево

```
student.yaml                 # ФИО, группа; в git не коммитить
subjects/<slug>/
  sample.docx                # эталон, только чтение
  title-fields.yaml          # после первого подтверждения титульника
  *.pdf                      # сюда кидают текущую работу, пока /report не забрал
  lab-01-.../                # создаёт Grok, не пользователь
    assignment.pdf           # распознанное задание
    *.pdf                    # лекции и прочий контекст той же работы
    assignment.md
    report.docx
```

Не создавать `inbox/`, `lectures/`, `materials/`. PDF в корне предмета — вход; после claim они лежат плоско в `lab-*`.

## Как работать (Grok)

Оркестрация — скилл `/report`. Команды только из корня.

1. `python tools/pickup.py --preview --json` — все PDF в корне предмета (не внутри `lab-*`), конвертация в `.preview/`. Прочитать каждый MD и картинки.
2. По **тексту**, не по имени файла: что задание (лаба/практика, «выполнить», цель/ход, варианты), что контекст (лекция, слайды, методичка). Несколько частей одного задания — одна лаба. Две разные лабы — два claim. Контекст отдельной lab-папкой не делать.
3. Нет `title-fields.yaml` с `confirmed: true` — онбординг титульника (рендер эталона, предложить find-строки), работу не начинать.
4. `python tools/pickup.py --claim --subject S --assignment ... [--context ...]`
5. Чеклист из задания, выполнить **каждый** пункт. Картинки задания — часть требования. Лекции — опора, не замена пунктов. Пока в `work/checklist.md` есть `- [ ]`, отчёт не готов.
6. Сборка: копия эталона, `patch_title` + `replace_body` (клоны блоков, не `Document()` с нуля), `render_docx`, осмотр всех preview PNG. Скилл `build-report`.

Нет PDF в предмете — сказать положить файлы в `subjects/<slug>/`, не просить вложение в чат.

## Жёсткие правила

- `sample.docx` не записывать. Сломанный `report.docx` — `--reset-docx`, не правка эталона.
- Word не генерировать через Composio/HTML. Composio — только если пользователь просит залить уже готовый `.docx`.
- Нет Postman/нужного MCP: `search_tool` → Composio connect → CLI с GitHub. Не останавливаться на «нет инструмента».
- Скрин/диаграмма в отчёт только после осмотра PNG и `ok: true`. Диаграммы — Mermaid, не image generation, если хватает кода.
- Ошибки CLI — на русском.
